# Conditional comparative model: occurrence-sensitive intuitionistic linear sequent calculus

**Status:** deferred design specification; not yet formalized or proved. This is a candidate extension after Spike 17's occurrence-sensitive capacity semantics, not an approved immediate build.

## 0. Cross-project prior-art gate (2026-11-20)

A review of Synesism's C-20 workstream found an existing occurrence-sensitive, usage-indexed lambda calculus: M263 (recursive terms and usage accounting), M264 (beta conserves usage exactly at linear redexes), M265 (typing, weakening, substitution and beta subject reduction), and M413 (parallel substitution, fusion laws, and reduction closure). These are not a complete ILL sequent calculus: the recorded limitations include no application typing rule, no tensor elimination term former, and no explicit exponential modality.

**Decision:** do not immediately build a second syntax/typing/substitution calculus. P091 already implements the finite ResourceOccurrence-to-usage-profile adapter in Python and Lean; do not reimplement it. First formalize the Agda M263 Usage-to-vector representation and token/rank correspondence, prove permutation naturality between the Lean positional profile and Python's explicit bijection, add M264's missing explicit k=2 beta-contraction witness, and test commutation with M263/M265/M413 renaming and parallel substitution. Only proceed with the ILL design below if a concrete gap remains that the Synesism calculus does not address—especially two-zone persistent/linear contexts, explicit ! promotion/dereliction, and cut admissibility. The candidate ILL layer must be justified by that gap, not by a desire to duplicate an existing lambda calculus.

This plan remains useful as a design specification for that distinct extension. Its rules are standard ILL; any possible Semplex contribution lies in provenance-aware, DAP-certified transformations, not in inventing the logic.

## 1. Research question

Can the resource fragment be upgraded from a finite capacity semantics to a syntax-directed proof system in which:

- linear assumptions are occurrence-sensitive and cannot be duplicated;
- persistent assumptions admit weakening and contraction;
- substitution/cut is admissible with explicit resource accounting;
- exponential rules explain when a linear assumption may be promoted to reusable evidence;
- every structural transformation carries a mechanically checkable preservation/loss certificate?

The target is to compare the actual derivability rules with classical FOL, dependent type theory, and the contextual/fibrational fragment—not merely compare four semantic toy models.

## 2. Syntax

Use formulas generated by:

    A, B ::= atom(p) | A ⊗ B | 1 | A ⊸ B | !A

The initial fragment contains tensor, tensor unit, linear implication, and the exponential. Additive connectives and quantifiers are deferred until the multiplicative/exponential core is stable.

A linear assumption is an occurrence (token, formula, provenance). Token IDs are globally unique within a context. Formula equality does not identify occurrences.

## 3. Judgments and contexts

Use a two-zone judgment

    Γ ; Δ ⊢ A

where:

- Γ is the unrestricted/persistent context;
- Δ is a finite multiset (or a list modulo permutation) of linear occurrences;
- every linear occurrence token is unique;
- A is the conclusion.

Persistent context exchange, weakening, and contraction are structural. Linear exchange is admissible, but linear weakening and contraction are not primitive rules.

For a first Lean implementation, use a list of persistent formulas and a list of tokenized linear occurrences, together with explicit permutation lemmas. A later refactor may use finite multisets once token identity and provenance are stable.

## 4. Core inference rules (conditional on the C-20 adapter gate)

### Identity

- Linear identity: Γ ; [(t,A)] ⊢ A.
- Persistent identity: if A ∈ Γ, then Γ ; [] ⊢ A.

### Multiplicatives

- Tensor right splits the linear context: from Γ ; Δ₁ ⊢ A and Γ ; Δ₂ ⊢ B, derive Γ ; Δ₁ ⊎ Δ₂ ⊢ A ⊗ B, with disjoint token sets.
- Tensor left replaces A,B in the linear context by A ⊗ B.
- Unit right requires an empty linear context.
- Unit left permits a linear unit assumption to be discarded.

### Linear implication

- Right: from Γ ; Δ, A ⊢ B, derive Γ ; Δ ⊢ A ⊸ B.
- Left: consume a proof of A and a continuation using B, splitting linear resources between the two premises.

### Exponential

- Promotion/right: from Γ ; [] ⊢ A, derive Γ ; [] ⊢ !A. The empty linear context is essential.
- Dereliction/persistent left: from Γ, A ; Δ ⊢ C, derive Γ ; Δ, !A ⊢ C.
- Persistent weakening and contraction operate only in Γ.

These are the intended ILL rules. The exact Lean inductive constructors must be written with token-disjointness conditions explicit; no rule may silently duplicate a linear context.

## 5. Metatheorems and counterexamples

1. **Exchange:** derivability is invariant under permutation of linear occurrences, preserving token identities and provenance.
2. **Persistent weakening:** adding an unrestricted assumption preserves derivability.
3. **Persistent contraction:** duplicate persistent assumptions may be identified without changing derivability.
4. **Linear non-contraction:** there is a derivable sequent with two distinct linear occurrences that becomes underivable if those occurrences are replaced by one occurrence. The canonical witness is the tensor introduction of A ⊗ A from two linear copies of A.
5. **Linear cut/substitution:** compose a derivation of A with a derivation using one linear occurrence of A, consuming that occurrence exactly once.
6. **Persistent cut:** a derivation of A from no linear resources may be substituted into any number of uses in the unrestricted context.
7. **Cut elimination:** prove by induction on formula structure and derivation height, or use a standard focused/multicut presentation if that makes the proof materially simpler. Do not assume cut elimination as an axiom.
8. **Soundness:** interpret contexts in a resource model (commutative monoid/phase-style semantics or a carefully defined multiset model) and prove every inference rule sound.

The existing capacity theorem is not a substitute for items 4–8. It is a finite semantic fragment that should become a model/countermodel for the proof system.

## 6. Distinction Admissibility interface

For every rule or transformation, record:

- input and output contexts;
- token correspondence (preserved, consumed, merged, or introduced);
- protected formula/observation family;
- persistent-use permissions;
- provenance transformation;
- exact resource delta;
- proof of semantic preservation or explicit counterexample.

The DAP contract must remain relative to a declared interface. It must not imply that all structurally valid transformations are admissible in every logic.

## 7. Comparison protocol

| System | Structural mechanism to compare | Required theorem |
|---|---|---|
| Classical FOL | substitution, equality replacement, unrestricted weakening/contraction | identify assumptions under which each rule is sound |
| ILL | linear vs persistent zones, tensor splitting, exponential promotion/dereliction | cut/substitution and contraction admissibility exactly in the persistent zone |
| Dependent type theory | identity elimination and substitution/transport | substitution derived from the identity eliminator, not from DAP alone |
| Contextual/fibrational semantics | reindexing, cartesian lift, descent/gluing | determine which transformations preserve fibers and protected observations |

## 8. Verification and audit gates

- Compile every new Lean module with the repository's pinned Lean 4.12.0 toolchain.
- Add explicit #print axioms entries for every named theorem.
- Reject sorryAx, custom axioms, untracked classical choice, or hidden assumptions. Standard axioms must be disclosed theorem by theorem.
- Add adversarial Python tests for duplicate token IDs, token collision with the surrounding context, wrong-formula merges, wrong-mode merges, invalid promotion with linear resources, and attempted linear contraction.
- Keep finite reference tests separate from theorem-level proof claims.
- Run the full fast suite, the slow non-Lean suite, and the Lean compile/audit suite independently; report exact counts and skips.
- Compare against Girard (1987), Benton (1995) on mixed linear/nonlinear logic, standard ILL proof theory, and categorical semantics before claiming any novelty.

## 9. Gated implementation sequence

**Stage A — required now (C-20 bridge):**
1. Add an explicit ResourceProfile abstraction to Semplex.
2. Define an injective token-to-variable assignment and a label-preserving formula-to-type map.
3. Prove in Lean that linear counts/support correspond to C-20 usage vectors on the mapped context.
4. Check the adapter under binders and parallel substitution, including M413's four fusion laws.
5. Compare theorem statements against M263/M265/M413 and record any mismatch as a failed bridge, not as a reason to weaken the target theorem.

**Stage B — only if the adapter exposes a genuine gap:**
6. Decide whether a separate syntax-directed ILL calculus is needed for the comparative demonstrator or for a missing persistent/exponential operation.
7. If yes, implement the formula grammar and tokenized linear context; then add the rules in §4.
8. Prove exchange, persistent weakening/contraction, linear non-contraction, linear/persistent cut, cut elimination, and soundness.
9. Integrate a derivation certificate into CSIR only after multiple existing fragments require the same fields.

The existing C-20 limitations—no application typing rule, linearity not yet a typing premise, tensor elimination still absent, and stronger normalization/confluence results open—are candidate gaps to test, not automatic authorization to build a parallel calculus.

**Novelty boundary:** every connective and structural rule above is established ILL. The possible Semplex contribution is a typed, provenance-aware certificate layer connecting derivability, resource accounting, protected operations, and declared loss—not the invention of linear logic or controlled contraction.
